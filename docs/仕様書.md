## 仕様書

### フロー

```
[ ユーザー (ブラウザ) ]
       │
       ▼
[ フロントエンド (React / TS) ] ── (Vercel等でホスティング)
       │
       │ HTTP Request (JSON)
       ▼
[ バックエンド (FastAPI / Python) ] ── (Cloud RunやRender等でホスティング)
       │
       ├──▶ [ データベース (PostgreSQL) ] : ユーザー情報、在庫データ、お気に入りレシピ
       │
       ├──▶ [ AI API (OpenAI / Gemini等) ] : 「余り物＋特売品」からオリジナルレシピを生成
       │
       └──▶ [ 外部レシピ API ] : 楽天レシピAPIなどから実在のレシピを検索
```

### 技術スタック
| レイヤー | 技術/ツール | 選定理由 |
| --- | --- | --- |
| フロントエンド | React, TypeScript, Vite | 高速な開発と型安全性の確保 |
| 状態管理 / 通信 | React Query (TanStack), Axios | APIからのデータフェッチとキャッシュ管理を劇的に楽にするため |
| スタイリング | Tailwind CSS (+ shadcn/ui) | 一人暮らし向けのシンプルで洗練されたUIを爆速で構築するため |
| バックエンド | FastAPI (Python) | Pythonの強力なデータ処理・AIライブラリ群をそのまま使え、型ヒント(Pydantic)によりReact(TS)との親和性も高いため |
| データベース | PostgreSQL (Supabase) | RDBの信頼性と、Supabaseを使えば認証（Auth）も手軽に実装できるため |
| ORマッパー | SQLAlchemy または SQLModel | FastAPIとの相性が抜群なため |
| 外部API (AI) | OpenAI API (GPT-4o mini 等) | 安価で高速に柔軟なレシピ提案テキストを出力させるため |
外部API (レシピ) | 楽天レシピ API | 日本向けの汎用的なレシピ検索として無料で使いやすいため |

### 注意
- FastAPIの非同期処理を活用する:
  - AI（LLM）への問い合わせや、外部レシピAPIへのリクエストは時間がかかる処理である。FastAPIの async def を使って非同期で実行することで、レスポンスの遅延を防ぎサクサク動くサイトにできる。

- APIスキーマの共有:
  - FastAPIは自動でOpenAPI（Swagger）のドキュメントを生成してくれる。これを活用してフロントエンド（React）向けのTypeScriptの型定義を自動生成（openapi-typescript 等を使用）すると、開発スピードが格段に上がる。
